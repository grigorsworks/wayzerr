# Test-driven development
1. Write a small failing test that states the wanted behaviour. Run it and watch it fail for the right reason.
2. Write the least code that makes it pass. Run all tests.
3. Clean the code up with tests green. Repeat for the next behaviour.
4. For a bug: first a test that reproduces it, then the fix.
Report the commands you ran and the final pass count; never say tests pass without having run them.
